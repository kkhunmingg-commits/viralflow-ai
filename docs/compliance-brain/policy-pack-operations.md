# Policy pack operations

Reviewed, signed policy data is loaded at runtime. Activating supported rule data with an already-trusted signer does not require a new application release. A new semantic category or scanner capability can require software changes. No production pack or trusted key is embedded in test fixtures. The following ingestion and review steps are helper-supported operations; no autonomous source watcher, production importer or signer is provisioned.

1. Discover an allowlisted official Thailand Shop article using `ingestOfficialPolicySource`. Its bounded fetch rejects redirects and non-text content. Supply an article extractor; page instructions are data, not executable instructions. Source hashes describe normalized article text.
2. Parse obligations into a candidate and preserve its origin (`AI`, `HUMAN`, or `DETERMINISTIC`). Text changes create a new source hash and candidate; `diffPolicySource` exposes additions/removals for review. Parsing never activates a policy.
3. Validate the candidate with server-authorized administrator approval, a SHA-256 regression report reference, positive test count and zero failed regressions. A missing effective date needs explicit acknowledgement, rather than a fabricated date. Rules and sources cannot expand scope during signing or activation.
4. Sign a strict `PolicyPackPayload` with an administrator-controlled Ed25519 private key. `SignedPolicyPack` contains `payload`, `checksum`, `algorithm`, `keyId` and base64 `signature`. The signature binds the payload and all envelope metadata; the checksum covers canonical UTF-8 JSON. Preserve the complete envelope in persistent storage.
5. Activate only a verified, approved pack. ID/version is immutable. A previous pack is retained for guarded rollback, and old source candidates become retired. SQL/admin service authority remains responsible for production transactions and cross-instance locking.
6. Resolve the active pack using trusted **server** public keys. Signature, key revocation, date, platform, country, region and semantic allowlist are rechecked on every load. Damaged or unavailable primary state can use a separately preserved verified last-known-good envelope. If neither verifies, return no pack and require review.

`PolicyRegistryStore` defines the adapter contract. `FilePolicyRegistryStore` implements it for a writable server directory outside the app bundle; it uses atomic file replacement, file sync, restrictive permissions and a bounded interprocess mutation lock. A held lock fails safely and is never automatically deleted as “stale.” Explicit disable writes a fallback tombstone. The directory must not be customer writable or publicly served. The local LIVE bridge uses this file registry. An ephemeral deployment filesystem cannot provide durable recovery across instances.

The production database runtime loads active version rows separately and retains only an in-process last-known-good envelope. Its outage lease expires 60 seconds after the successful lookup started; slow or backwards-clock reads cannot renew that lease. A fresh empty lookup clears fallback, and signature/trust checks run again before cached use. A retirement on another instance can remain unseen during the remaining lease if database access fails. Immediate distributed revocation, durable restart fallback and signer-key propagation are deployment responsibilities, not guarantees of this process-local cache.

Active-state commits occur before replacement of the fallback, so a failed state write cannot expose an uncommitted update through last-known-good recovery. If only fallback writing fails after an active commit, the active pack remains persisted and the prior fallback remains available; the operation reports failure so the administrator can repair storage. Database adapters should use a transaction for the complete activation where supported.

The unit helper `createSignedPolicyTestFixture` generates a fresh in-memory signing key and verifies its synthetic pack. Its signer is never added to runtime trust. The researched Thailand rules remain `PARSED / HUMAN_REVIEW_PENDING` until the production review process completes.
